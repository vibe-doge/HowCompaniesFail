# 公司败局案例集

**每期解剖一家真实倒闭的公司。讲可查证的事实，写能用的避坑清单。**

不写成功学，只写失败学。

## 这是什么

一本**公司败局案例集**。

这里不教你怎么创业，只讲别人是怎么死的。收录的每个坑都有人已经掉进去过，每条都带出处，法院文书或公开报道，能自己核对。

每条案例是**一篇文章**：开头先把光环和结局的数字反差摆出来，再讲它是一步步怎么走到这一步的，最后落到五条能用的避坑清单。

## 站点

**https://vibe-doge.github.io/HowCompaniesFail/**

- **首页**（`/`）—— 就是一段概要：这个站在做什么、为什么从失败看起。不放欢迎页，也不放筛选器。
- **文章** —— 全部文章列在左边目录里，从任何一页都能直接跳到别条。
- **收录标准与立场**（`/about`）—— 来源怎么分档、引什么、不做什么，也在左边。

顶栏只有站名和搜索框，没有导航菜单。仓库名是 `HowCompaniesFail`，站点挂在 `/HowCompaniesFail/` 子路径下，所以往后贴链接都要带这个前缀。

## 收录标准

- **法院文书**：有案号，能在中国裁判文书网或全国企业破产重整案件信息网查到。
- **公开报道**：只有公开报道，没有案号、判决书或官方通报。这一类会在来源栏写明。

区别只有这一条：公开报道那一档，数字照样要有出处，不从报道里凭印象取。

## 事实核查

- 关键争议点用官方定性表述。比如创始人「失联」必须依据官方通报，不能写成「被抓」或「逃往海外」。
- 免责声明里不出现任何具体媒体名称，统一写「综合公开报道及法院公开文书」。

## 立场

这个仓库不卖课、不接软文、不推代账 / 加盟 / FA。这几类本身就是坑，这个号拆的就是它们。

## 本地跑站点

```bash
npm install
npm run dev        # 本地预览
npm run build      # 构建
npm run check      # 校验条目格式
npm run check:base # 校验站内链接都带了 base 前缀（要 build 之后跑）
```

## 加一条新案例

复制 `docs/entries/_模板.md`，改名成 `NNN-公司名.md`，照模板填。

格式规则写在 [CLAUDE.md](CLAUDE.md)，`npm run check` 会校验字段、七节顺序、免责声明是否逐字等于模板、避坑清单是不是正好 5 条，还会拦住正文里冒出来的「第 N 张」和问号（全篇写陈述句，不向读者发问）。

仓库自带两个 skill，放在 `.claude/skills/` 下，用 Claude Code 打开这个仓库时自动可见：

- `SKILL.md` —— 七节结构、深度从哪来的七个动作、写作禁令、去 AI 味清单、发布前自检
- `references/exemplar-annotated.md` —— 一篇成品逐段拆解
